============================================================
 PART A. Oracle Cloud Always Free で常時ホスティング
============================================================

■ A-1. アカウント作成
  - https://www.oracle.com/cloud/free/ で「Always Free」アカウント作成
  - クレジットカードと電話番号の確認が要る（Always Free枠は無料。有料化しない限り課金されない）
  - リージョンは「東京(ap-tokyo-1)」か「大阪」を選ぶと日本から速い
    ※ Always Free の Ampere(ARM) 枠は人気で「Out of capacity」になりがち。
      その場合は時間帯・リージョンを変えて再試行するか、AMD Micro 枠で妥協する。

■ A-2. VM(コンピュート・インスタンス)を作成
  - メニュー: Compute → Instances → Create Instance
  - Shape(重要):
      第一候補) VM.Standard.A1.Flex（Ampere ARM, Always Free枠: 4 OCPU / 24GB まで無料）
                → 平凡投票には 1 OCPU / 6GB で十分すぎる
      代替)     VM.Standard.E2.1.Micro（AMD, Always Free。非力だがこのアプリなら動く）
  - OS(Image): Canonical Ubuntu 22.04（推奨。以降の手順は Ubuntu 前提）
  - SSH鍵: 「Generate a key pair」で秘密鍵をDLして保管（後で SSH ログインに使う）
  - Networking: パブリックIPを割り当てる（デフォルトでOK）
  - 作成後、割り当てられた「Public IP アドレス」を控える

■ A-3. ファイアウォールを2箇所開ける（← 一番ハマる所）
  Oracle は「クラウド側」と「OS側」の2重ファイアウォールがある。両方 80/443 を開ける。
  (1) クラウド側: VCN → Security Lists（またはNSG）に Ingress ルール追加
        - 0.0.0.0/0 / TCP / 80
        - 0.0.0.0/0 / TCP / 443
  (2) OS側: SSHログイン後に実行
        $ sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
        $ sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
        $ sudo netfilter-persistent save
      （Ubuntu の Oracle イメージは iptables で絞っている。上記で 80/443 を通す）

■ A-4. サーバーに必要なものを入れる（SSHログイン後）
  $ sudo apt update && sudo apt -y upgrade
  # Node.js 20（このアプリは Node 20 系で動作確認済み。v20.19.2）
  $ curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
  $ sudo apt -y install nodejs
  # better-sqlite3 はネイティブモジュール。ビルドツールを入れておく（prebuild が無い時の保険）
  $ sudo apt -y install build-essential python3 git nginx
  # プロセス常駐マネージャ pm2
  $ sudo npm install -g pm2

■ A-5. 平凡投票を配置して起動
  $ git clone https://github.com/moka0502/heibon-vote.git
  $ cd heibon-vote
  $ npm ci          # package-lock 通りに依存を入れる（better-sqlite3 がビルドされる）
  # 初回起動テスト（Ctrl+C で止める）
  $ node server/index.js
      → 「heibon-vote server listening on http://localhost:4322」が出れば成功

  # pm2 で常駐 + サーバー再起動やOS再起動でも自動で立ち上がるようにする
  $ pm2 start server/index.js --name heibon-vote
  $ pm2 save
  $ pm2 startup       # 表示されたコマンドを1回コピペ実行（OS起動時の自動起動を登録）

  ★ デプロイ（コード更新）時の手順（重要・CLAUDE.md にも記録済み）:
     $ cd ~/heibon-vote && git pull && npm ci && pm2 restart heibon-vote
     ※ push しただけ / git pull しただけでは反映されない。pm2 restart まで必須。
     ※ サーバー再起動で questions-seed.json の変更も DB に反映される（起動時 seed）。

■ A-6. trust proxy を設定（nginx の背後に置くので必須）
  nginx をリバースプロキシにする前に、server/index.js に1行足す。
  （レート制限が「全ユーザー同一IP扱い」になって審査官まで 429 で弾く事故を防ぐ。
    コード内の該当コメント「本番デプロイ時の必須設定」参照）
  server/index.js の「app.use('/api', generalApiLimiter);」の直前に:
        app.set('trust proxy', 1);
  を追加してコミット→push→VPSで git pull → pm2 restart。

 PART B. ドメイン + HTTPS（Capacitor は https 必須）
============================================================
capacitor.config.json は cleartext:false = https 必須。生IPでは Let's Encrypt 証明書が
取れないので「ドメイン名」が要る。

■ B-1. ドメインを用意
  ★★ 最重要: 「Whois情報公開代行」を必ず付けること ★★

  【WHOISとは】
    ドメインを買うと「持ち主は誰か」を登録する国際的なルールがあり、その情報は
    誰でも無料で検索できる（https://www.whois.com/whois/ 等）。これがWHOIS。
    購入時に入力した【氏名・住所・電話番号・メールアドレス】が、何も対策しないと
    そのまま世界中に公開される。App Storeで公開される「開発者名(本名1行)」より
    はるかに露出が大きいので、ここは必ず対策する。

  【対策】
    「Whois情報公開代行」「WHOIS代理公開」「ドメインプライバシー保護」等と
    呼ばれるオプション。自分の情報の代わりに販売会社の情報が表示される。
    今は無料で標準装備の会社が多い。

  【どこで買うか】おすすめ順
    ムームードメイン       … 標準で無料。日本語。個人開発なら一番ラク
    Xserverドメイン        … 標準で無料。日本語。VPSも同社で揃えられる
    Cloudflare Registrar   … 標準で無料。最安(原価販売)だが英語UI
    ⚠️ お名前.com          … 【新規登録と"同時"なら無料、後から付けると有料】
                             一番ハマりやすいので注意
    .com で年1,500円前後。

  【買ったら必ず自分の目で確認】
    https://www.whois.com/whois/ で自分のドメインを検索し、
    自分の氏名・住所が出てこないことを確認する。
    販売会社名や「REDACTED FOR PRIVACY」と出ていればOK。

  【無料で済ませる選択肢】
    DuckDNS（例: heibonvote.duckdns.org）はドメインの持ち主がDuckDNS社なので、
    そもそも自分の情報がWHOISに載らない。ただし「借り物のURL」感が出るため、
    転職活動の実績として見せるなら独自ドメイン+代理公開を推奨。

  取得したら DNS の A レコードを「VPSのPublic IP」に向ける。

■ B-2. nginx をリバースプロキシに設定
  $ sudo nano /etc/nginx/sites-available/heibonvote
  --- 以下を貼る（server_name は自分のドメインに置換）---
  server {
      listen 80;
      server_name YOUR-DOMAIN;        # 例: heibonvote.example.com
      location / {
          proxy_pass http://127.0.0.1:4322;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
      }
  }
  ---
  $ sudo ln -s /etc/nginx/sites-available/heibonvote /etc/nginx/sites-enabled/
  $ sudo nginx -t && sudo systemctl reload nginx

■ B-3. HTTPS 化（Let's Encrypt / certbot、無料・自動更新）
  $ sudo apt -y install certbot python3-certbot-nginx
  $ sudo certbot --nginx -d YOUR-DOMAIN
      → メール入力・規約同意。証明書取得と nginx への https 設定を自動でやってくれる
      → 「https://YOUR-DOMAIN/」でアプリが開けば成功
  自動更新は certbot が cron/timer で入るので放置でOK（$ sudo certbot renew --dry-run で確認）

■ B-4. 疎通確認（審査官もここを触る）
  - スマホ/PC のブラウザで https://YOUR-DOMAIN/ を開き、クイズが最後まで動くか
  - https://YOUR-DOMAIN/privacy.html が開くか（プライバシーポリシーURLに使う）

 PART C. capacitor.config.json を本番ドメインに差し替え
============================================================
  capacitor.config.json を編集:
    "appName": "平凡投票",                       ← heibon-vote から変更（表示名を統一）
    "server": { "url": "https://YOUR-DOMAIN", "cleartext": false }
  さらに（任意だが推奨）シェア文/画像にURLを入れるならこのタイミングで。
  変更したら commit → push。（アプリ側は次回リロードで反映、SW更新なら sw.js の
  CACHE_NAME を上げる）

 PART E. Mac で iOS プロジェクト作成 → Xcode ビルド
============================================================
（この PART は macOS + Xcode が必須。Linux/devcontainer では完結しない）

■ E-0. 事前準備
  @capacitor の core / cli / ios はすべて 8.5.0 に揃っている（2026-08-18 時点。
  以前あったメジャー不一致は解消済み）。バージョンを触る必要はない。
  ※ Mac を持っていない場合、この PART E は Codemagic（クラウドmacOS）が
    codemagic.yaml のとおり自動でやるので、手作業は不要。
    以下は Mac が手元にある場合の手順。

■ E-1. iOS プロジェクトを作る
  $ npm ci
  $ npx cap add ios
  $ npx cap sync ios
      ※ cap add ios は CocoaPods が要る（$ sudo gem install cocoapods）

■ E-2. アイコン・スプラッシュを各サイズ展開
  マスターアイコンは既に www/icons/icon-1024.png がある。
  $ npm install -D @capacitor/assets
  $ npx @capacitor/assets generate --ios
      → iOS 用の全サイズ・スプラッシュが ios/ プロジェクトに生成される

■ E-3. Xcode でビルド
  $ npx cap open ios     # Xcode が開く
  - Signing & Capabilities: 自分の Apple Developer チームを選択（Bundle ID = com.moka0502.heibonvote）
  - 実機 or シミュレータで起動し、WebView が https://YOUR-DOMAIN を開いて動くか確認
  - リモートURL型なので、サーバーが落ちていると真っ白 → 提出前は VPS 稼働を必ず確認

 PART F. App Store Connect 登録・提出
============================================================

■ F-1. アプリ登録
  - https://appstoreconnect.apple.com/ → マイApp → 新規App
    名称: 平凡投票 / Bundle ID: com.moka0502.heibonvote / 言語: 日本語 / SKU: 任意

■ F-2. 掲載素材
  ★ 掲載素材と入力文はすべて appstore/ に用意済み。
     → appstore/掲載情報_コピペ用.txt を開いて、そのまま貼っていくだけ。

  - アプリアイコン(1024x1024): www/icons/icon-1024.png を使用
  - スクリーンショット: appstore/screenshots/framed/*.png（1290x2796 = 6.9"、6枚）
      6.9" だけ登録すれば他サイズは App Store 側で自動縮小される。
      撮り直しは $ node appstore/generate-screenshots.js
  - 説明文/キーワード/プロモーションテキスト/サブタイトル:
      appstore/掲載情報_コピペ用.txt にそのまま貼れる形で記載
  - プライバシーポリシーURL: https://YOUR-DOMAIN/privacy.html

■ F-3. App Privacy 申告（実態と一致させる。ここが要注意）
  ★ 各設問への回答は appstore/掲載情報_コピペ用.txt の「App Privacy 申告」節に
     項目ごと（Identifiers / User Content / Sensitive Info）で記載済み。
  平凡投票が集める情報（www/privacy.html と実装に一致）:
    - 年代・性別・血液型・利き手（任意。未選択なら取得しない）
    - 匿名 voterId（localStorage の UUID。端末識別子に相当）
    - クイズの回答内容
    - お題提案フォームの投稿文
    - 氏名・メール等の個人特定情報は取得しない
  申告のポイント:
    - 「Identifiers（匿名ID）」「User Content（回答・提案）」等に該当をチェック
    - 用途は「App Functionality（アプリ機能）」。トラッキング/広告目的では使っていない
    - 第三者共有なし、ユーザー追跡なし（＝ATT プロンプト不要。広告は初回提出に入れない方針）

■ F-4. 審査で落ちないための要点（Guideline 対策・CLAUDE.md 準拠）
  1. 【最重要】提出時に VPS が確実に稼働（審査官が実際に操作する。落ちてると即 Reject）
     → pm2 で常駐、証明書有効、https で最後まで遊べることを直前に確認
  2. App Privacy 申告と www/privacy.html の内容を一致させる
  3. Guideline 4.2(Minimum Functionality): 独自アイコン・スタンドアロン表示・GSAP演出で
     「ただのWebサイトのラップ」に見せない（実装済み）
  4. Guideline 2.1(App Completeness): クラッシュ/壊れリンク/無反応ボタンを潰す
     （堅牢性テスト・意地悪テストは実施済み。x-powered-by無効化・400/413化・
       セッション横取り対策済み）
  5. レート制限が審査官を誤ブロックしないよう trust proxy を設定（PART A-6）
  6. 広告(AdMob)は初回提出に入れない。承認実績を作ってからアップデートで追加
